# Separate Control Console and Notebook Key releases

AMZ.API publishes ordinary renderer changes as Control Console Releases through GitHub Pages without changing the installed desktop app. A local Amazon or security capability instead becomes one Notebook Key Release built from the same tagged source for macOS and Windows; background updates are enabled only when the publisher-signed workflow injects the exact `publisher-signed-v1` package marker, and installation still requires an explicit “更新並重啟” action. The tag commit must already belong to `origin/main`, and each platform runner rebuilds from that same source before signing; Windows metadata must contain one publisher name exactly equal to the actual Authenticode certificate identity. Once installation handoff begins, main closes credential editors and gates new Amazon／credential IPC until restart; a synchronous throw or later updater error rolls that gate and the renderer busy state back. The Pages renderer feature-detects the new updater bridge so an older Notebook Key can show the final-bootstrap instruction without calling a missing IPC. Unsigned CI artifacts keep the default `disabled` marker. Every existing installation therefore needs one final manual Bootstrap Notebook Key before routine desktop releases can use the trusted update chain. The update-feed visibility decision remains separate: the current protected installer boundary must not become a public GitHub Release feed without explicit approval.
