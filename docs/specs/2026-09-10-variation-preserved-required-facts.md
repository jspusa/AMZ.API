# Preserve an existing product fact required by variation Preview

Issue #228. On 2026-09-10 the reviewed local diagnostic candidate established the actual failing branch: Amazon HTTP 200 returned ERROR 90220 / `contains_liquid_contents` / `MISSING_ATTRIBUTE`, while the fresh source listing already contained nonempty data for that attribute. The fill-only descriptor intentionally excluded it, leaving no usable recovery control. This observation does not establish the exact answer or imply the existing value is valid under every PTD constraint. The candidate was restored to the verified 0.1.61 CI app with unchanged vault bytes after the read-only Preview; no formal Amazon mutation occurred.

The workbench must offer a deliberate way to retain that existing answer and include it in the next variation submission. Keep ordinary missing-fact inputs fill-only. Use a separate name-only `preserveRequiredFields` selection and main-produced `preservedRequiredFields` descriptors; renderer input never supplies replacement values for this path. Display the current answer read-only, explain why Amazon needs it, leave the selection unchecked, and show the same before/after answer in the preview disclosure. A new selection invalidates the old Preview. Context changes clear old selections and evidence.

Authority is limited to an exact required attribute identity from trusted, bounded Preview metadata for the current source, target, marketplace, account, PTD and preparation. An optional-field candidate or arbitrary renderer name does not grant preservation authority. Initially support a complete, single-row scalar product fact with unambiguous selectors and a declared, supported CHILD PTD shape. Reject protected commerce, fulfillment, content, image, identity, relationship and variation-dimension attributes; malformed, cross-market, repeated or unsupported values remain blocked with a clear reason. Existing `false` and `0` are meaningful values, never blanks.

Main copies the entire original attribute array without changing values, selectors or ordering. It must not use the existing fill-only patch builder, which can rebuild selectors or reorder rows. Include the selected names and an exact fact digest in the proposal fingerprint and durable recovery evidence. Re-read before native approval and dispatch; any relevant value, selector, source, target, identity, PTD or context drift invalidates the operation. GET reconciliation must prove both the relationship and the preserved fact; an unknown result permits read-only recovery, never resend. Existing fingerprints and recovery behavior remain compatible when this option is absent.

An immutable fact can still be included unchanged in a valid submission. This is distinct from changing its value: the exact whole-attribute payload must pass Amazon Validation Preview before native approval, durable claim and one formal PATCH. No automatic checkbox, guessed answer, generic JSON editor, background retry or approval bypass is added. Contradictory or filtered ERROR receipts must continue to grant no Preview ticket.

Validation must reproduce the existing-false failure at the production Preview seam before the fix; prove an explicit selection produces an exact unchanged fact patch and a usable valid preview; exercise forged selections/values, incomplete facts, readonly facts, drift, ledger recovery and unknown receipts; and verify the renderer's readable answer, unchecked control, state reset and preview disclosure. Run both independent review axes, the full repository check and production audit. Release 0.1.62 only from reviewed exact source and verified CI artifacts; source tests, Pages deployment, installed app, protected downloads and live Preview remain separate claims. The original live case is not fixed until the actual account reaches a usable recovery flow and a fresh Preview result is recorded. Formal Amazon submission requires separate per-SKU authorization.

Official references checked 2026-09-10: [PTD editable semantics](https://developer-docs.amazon/sp-api/docs/product-type-definition-meta-schema) permit immutable properties to remain required; [partial listing updates](https://developer-docs.amazon/sp-api/docs/partially-update-a-listing) use entire attribute patches. These documents do not guarantee that this particular unchanged fact will be accepted by Amazon; live Preview supplies that evidence.
