# 效期與清售風險表格可讀性

使用者於 2026-09-13 回報「品項／批次」到「核對」的表頭與後方欄位擠在一起。此修正為 Control Console Release，沿用已安裝的 Notebook Key 0.1.72，不提高桌面版本。

## 問題與重現

- 原生 App 在約 1961px 寬視窗仍使用約 1080px 的效期視窗；產品名稱過度換行，右側銷速、缺口與核對不在可用欄寬內。
- 實際 `InventoryHealthPanel`、完整樣式及合成資料的畫面重現八欄寬度為 `[176,343,118,176,167,0,0,0]`。既有通用五欄設定分配完 100% 寬度，套入八欄 fixed table 後使最後三欄為零。
- 重現與修後都需以實際 component／CSS 量測及截圖核對；不能只以 JSX 仍有八個欄名當作已解決。

## 變更契約

- 表格八欄都有明確可讀的空間，品名、庫存、日期、已確認餘量、銷速、缺口與核對按鈕不重疊或消失。
- 表頭可按語意換行，日期與數字保持可辨識，說明文字正常換行；不隱藏必要資料或以省略號取代判讀所需內容。
- 寬螢幕可使用更多既有視窗空間。窄螢幕保持適當欄寬，提供可發現且能以鍵盤操作的橫向捲動區；右側核對與其展開內容必須可達。
- 保留全部 FBA、銷售偏慢、清售風險、待確認與預估可清完的篩選，搜尋、批次核對、載入與儲存狀態維持原行為。
- 不修改庫存或效期計算、來源完整度、未知值、批次確認 API、行事曆門檻、Amazon 或安全能力；人工即期品及促銷不受影響。

## 驗收

1. 原本重現的寬螢幕與 1440px 畫面，最後三欄不再為零寬度；所有欄位及按鈕可見且不互相遮蓋。
2. 窄螢幕與放大字體仍可閱讀及操作右側核對；展開內容可用，關鍵說明不遭裁切。
3. 完整既有檢查、樣式 fingerprint／build 驗證與 production audit 通過；兩軸 review 無未解問題。
4. 發布 exact source 的 Pages，核對線上實際資產，並在原生 AMZ.API 的健康結果表格確認修正。
5. 本修正完成不代表原始完整效期同步完成。.72 已安裝並連線，但一次真實同步仍有 `FBA_INBOUND_UPSTREAM_UNAVAILABLE`，該獨立問題繼續診斷，不盲目重試或把 partial 標為成功。
