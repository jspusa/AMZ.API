# 庫齡報表按完整值選擇區間

Issue [#261](https://github.com/jspusa/AMZ.API/issues/261)。版本 0.1.68，base `ad04eaa33d07597112dcee034c515f09a7d2ded0`，分支 `codex/health-age-values-20260913`。

## 問題與證據

已安裝的可信 0.1.67 原生首頁連線成功。第一次全 FBA 效期與銷速同步以「Amazon FBA 庫齡報表的『0–30 天』缺值。（REPORT_FORMAT_UNSUPPORTED）」結束，沒有重試。這與 0.1.67 已修正的同義欄衝突是不同症狀。

公開 `AgedInventoryReads.read` 測試已重現：有效 0–90 原值與空白三細分並存時，原本只看標題是否存在而優先採細分，導致可用資料也遭拒絕。181–365 的標準組空白而替代組完整有同樣機制，另有先紅再綠的測試。

[Amazon 官方欄位清單](https://developer-docs.amazon/sp-api/docs/report-type-values-fba#fba-manage-inventory-health-report) 列出這些範圍；未規範空白語意、更新同步或 App 回退優先序。完整 live raw row 未保留，合成測試不是該真實資料列，後續欄位是否完整仍需原生驗收。

## 行為與邊界

候選組先須具備完整標題，再按原優先順序核對所有資料列。近期 0–30／31–60／61–90 完整時沿用細分；任一列空白時，只有全部資料列的 0–90 都有效才能改採它。181–270／271–365 亦保留優先序，不足時才採所有列完整的 181–330／331–365。

整份報表選同一組區間，保留原始數量，不補零、不拼接候選區間、不把彙總與細分一起加總。回退前核對的候選若有非空非法值或超出安全數量，仍拒絕；沒有任何完整路徑仍保留原錯誤。完整優先組成立時，保留原有不採另一組的行為。區域尾桶、SKU／站點／context、重複標題與官方費用完整性規則不改，沒有 FBA 現存批次餘量證據時不得產生確定的效期缺口。

## 驗收

1. 在公開 reader seam 重現空近期細分與空 181–365 標準組的錯誤，修正後只投影完整替代區間，逐列及全站總數正確。
2. 覆蓋反向欄序、混合完整／空值資料列、各細分缺值、明確零、缺標題／值／有效替代路徑、非法值／overflow、重疊拼接拒絕及區域尾桶。
3. 原完整細分優先、身分／context／重複欄防護、費用 partial／unavailable 及無部分全站合計仍通過。
4. `npm run check`、`npm audit --omit=dev`、兩軸 review 與同來源 CI／產物核對後發布；可信新版安裝後才進行全 FBA 原生驗收。
5. 來源／fixture、發布、安裝、真實全 FBA 結果、員工下載與真人生物辨識分開記錄。不為驗收修改 Amazon，也不在舊版盲目重啟失敗報表。
