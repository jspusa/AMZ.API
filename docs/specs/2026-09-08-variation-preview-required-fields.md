# Turn Amazon Preview requirements into editable product fields

Installed 0.1.60 now prepares the original standalone PET_FOOD attach successfully, preserving both read-only dimensions and the matching existing theme. The actual Amazon Validation Preview then returned a missing Contains Liquid Contents requirement. The workbench still showed only the two preserved dimensions and said the data was complete, leaving the user no way to supply the required fact. This is the original usability problem, now isolated after removing the earlier blockers. No formal Amazon write was performed.

| Requirement | Acceptance |
|---|---|
| ★ Use actual Preview requirements | Capture only bounded, relevant validation issue metadata from the exact Preview operation. Resolve requested attributes against the current CHILD PTD and bind hints to the correct marketplace, account context and source SKU. Do not expose raw Amazon responses or make renderer hints authoritative. |
| ★ Provide an input and a next step | After a missing-field Preview, show the requested editable product fields in the existing form, retain the user's other values, and say what remains incomplete. The user can choose a boolean or enter other supported schema values, then run a new Preview. Never silently choose false or invent a product fact. |
| ★ Handle limited issue metadata safely | Attribute names must exist in the CHILD PTD. If Amazon omits names, any supported fallback must be unambiguous and schema-grounded; otherwise explain what is unresolved and provide an intentional way to select a supported field. Never infer writable paths from free-form error text alone. |
| ★ Preserve update safeguards | Read-only dimensions/theme remain unchanged and omitted from PATCH. Product facts use existing safe validation/patch rules. New inputs invalidate old Preview evidence. Native confirmation, durable idempotency, unknown-state reconciliation and no blind retry remain intact. |
| ★ Prove the whole recovery flow | Production public seam regression must reproduce the missing-field failure, return actionable fields, accept explicit user input, pass a fresh Preview, and prove unchanged facts are not broadly overwritten. Mounted renderer tests cover the same recovery and missing/ambiguous metadata. |
| ★ Deliver and verify | Run repository checks and independent Standards/Spec reviews, release a new Notebook Key version, preserve the installed app's vault, and use the original source/target in the installed app through actual Amazon Preview. Formal Amazon mutation remains outside acceptance. |

Official [Listings issue troubleshooting](https://developer-docs.amazon/sp-api/lang-en_EN/docs/listings-items-api-issues-troubleshooting) documents multiple missing-value codes. The [Listings OpenAPI model](https://raw.githubusercontent.com/amzn/selling-partner-api-models/main/models/listings-items-api-model/listingsItems_2021-08-01.json) makes issue attribute names optional and defines the missing-attribute category. PTD titles are [schema annotations](https://json-schema.org/understanding-json-schema/reference/annotations), not authoritative identifiers. Any exact, unique title mapping is this application's conservative recovery strategy, followed by explicit user input and a fresh Preview; it must not be described as an official identity guarantee.
