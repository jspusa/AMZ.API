# 商品圖片改為一小時暫存

Issue #294。Jasper 明確將原七天政策改為「一小時就好」；這項決定取代 [原批次圖片規格](2026-09-image-folder-batch.md) 的七天期限，不改變完整替換、30 SKU／每 SKU 10 張或一次原生批次批准。

## 已定案行為

- 新圖片自準備時起保留一小時；receipt、公開取圖與清理共用有效期限。Amazon 沒有保證會在一小時內取圖；到期後仍需要圖片時，必須重新準備並核對，不自動重送 Amazon。
- 既有圖片依原建立時間加一小時縮短期限，且不超過原期限。無可信建立時間的舊物件只取得一次固定的一小時遷移緩衝；重新讀取或發布不延長期限。原始 metadata／reservation 的一致性仍是刪除前提。切換一小時政策後停止舊 v1 上傳，保留符合期限的既有圖讀取，避免刪除後以相同 UUID 重新建立舊網址。
- Main 只接受符合一小時政策且剩餘超過十分鐘的來源。完成整批預檢後，再核對所有可送出列；核對票證截止時間取既有十五分鐘與最早圖片期限減十分鐘的較早值。
- 原生批准前、每個 SKU 提交前與最後 transport fence 都檢查來源有效性。只允許使用者明確重新準備已驗證且快到期的來源；unknown 保持 GET-only，不自動重傳。
- 固定清理工作每五分鐘排程一次，仍只有 server 可選擇到期圖片；實際刪除並證明不存在後才釋放預留額度。清理不重置當日請求配額，所需最小計數資訊在 UTC 隔日清除。GitHub 排程延遲與網址到期分開，不能把過期當成物件已刪除。
- 前台顯示「1 小時」及實際到期日期時間。儲存的 10 GiB／10,000 操作上限是本產品預留額度限制，不能當成平台方案容量或實際已用／剩餘空間。

## 驗收

在原 public seams 以 fake clocks 驗證一小時 receipt、十分鐘邊界、舊來源遷移、30 SKU 慢速準備、批准／提交期间到期、unknown 不重試與刪除後配額回收。保留完整檢查、production audit、兩軸審查、線上來源／產物／安裝證據。真實五資料夾測試驗證 45 張準備與五 SKU 預檢；正式 Amazon 更新仍不屬於程式驗收。
